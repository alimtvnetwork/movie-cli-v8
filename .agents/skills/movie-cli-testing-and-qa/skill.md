# Movie CLI Testing and QA Skill

## Overview

Quality assurance for `movie-cli-v8` spans unit tests for filename cleaning and database operations, integration tests for TMDb API mocks, and end-to-end tests verifying CLI command execution, popout extraction, and undo/redo state restoration.

## Test Inventory & Structure

### Test Suites Across Packages
- `db/media_test.go` & `db/open_test.go`: SQLite connection, table schemas, CRUD methods, migrations, and cascading deletes.
- `doctor/checks_test.go`: Validates diagnostic detection of PATH drifts, deploy mismatches, and worker presence.
- `tmdb/client_test.go`: HTTP mock testing for search responses, 429 rate limiting, and fallback resolution.
- `updater/repo_test.go`: Tests git output parsing and handoff worker staging.
- `cmd/e2e_test.go`: End-to-end CLI command verification using temporary directories.
- `cmd/undo_redo_e2e_test.go`: Verifies multi-step move/rename operations followed by sequential undo and redo passes.
- `cmd/movie_popout_integration_test.go`: Verifies extraction of nested video files and `.temp/` compaction.
- `cmd/preview_parity_test.go`: Ensures that dry-run previews exactly match executed operations.

### Centralized Test Inventory (`.ai-memory/test-inventory.json`)
The repository maintains a centralized test manifest generated by `03-ai-scripts/33-test-inventory-generator.py`:
- Tracks all test functions, file paths, and target functions.
- Records test duration, performance tiers (`fast` vs `slow`), and execution timestamps.
- Enables targeted incremental test execution during release cycles.

## Strict Rules & Execution Guardrails

1. **NO Tests Without Owner Command (Hard Prohibition):**
   - In accordance with `.ai-memory/strictly-avoid.md`, AI agents MUST NOT execute unit tests or CI runners during standard development, refactoring, or documentation turns unless the repository owner explicitly commands it.
   - When running `03-ai-scripts/06-cicd-local-runner.py`, agents must pass `--no-tests`.
2. **Filesystem Isolation (`t.TempDir()`):**
   - Tests must never operate against actual user home directories, media libraries, or real database files.
   - All tests creating files, moving paths, or opening SQLite databases must use Go's `t.TempDir()` to guarantee ephemeral isolation.
3. **No Network Dependencies in Unit Tests:**
   - External TMDb and DuckDuckGo calls must use mock HTTP handlers (`httptest.Server`) or simulated responses to prevent flakiness or rate limiting.

## Targeted Test Execution (When Commanded by Owner)

```sh
# Run specific package tests
go test -v ./db/...
go test -v ./cleaner/...
go test -v ./doctor/...

# Run specific individual test function
go test -v -run TestUndoRedoCycle ./cmd/...

# Run test inventory generator
python 03-ai-scripts/33-test-inventory-generator.py
```
